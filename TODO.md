- [x] Automatic memory recall at session start (2026-08-03): `Orchestrator::recall_prior_memories` (`core/orchestrator.rs`), called once from `run_stage_machine` right after `Context::new`, before `Stage::Scope` begins. - [x] Resource-limited sandboxing for cargo subprocesses (2026-08-03): `cargo_check`/`cargo test`/`cargo tree --duplicates` had wall-clock timeouts (30s/60s/120s/20s) but no memory/CPU caps. Added `orchestrator::cargo::limit_resources(cmd, wall_clock_secs)` — sets `RLIMIT_AS` (4 GiB, a fixed ceiling) and `RLIMIT_CPU` (`wall_clock_secs * available_parallelism()`, since CPU *time* on a parallel build can exceed wall-clock time several-fold) via an `unsafe { cmd.pre_exec(...) }` closure that only calls `libc::setrlimit` (async-signal-safe, no allocation) — before spawning `cargo` in `orchestrator/cargo.rs::cargo_check` and all three cargo spawns in `agent/protocol.rs` (`run_cargo_check`, and both halves of `run_build_and_test`). Rlimits are inherited across fork/exec, so this also bounds every rustc/build-script/proc-macro process cargo itself forks, not just the top-level `cargo` process. `cargo_dupes` (`cargo tree --duplicates`) wasn't given a limit — it doesn't compile anything. Unix-only (`setrlimit` is POSIX; no-op stub on non-unix, though the project doesn't currently target Windows). Added `libc` as a direct dependency (`Cargo.toml`) — it was already resolved transitively, so this doesn't add a new crate to the dependency tree. Verified with an end-to-end test that spawns a real `sh -c 'ulimit -v; ulimit -t'` child and asserts the kernel actually enforced the requested limits, not just that `pre_exec` was registered.
