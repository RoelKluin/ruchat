# Ruchat

Ruchat is a local-first, Rust command-line tool for AI chat and multi-agent
software-engineering orchestration, built on **Ollama** (local LLM inference)
and **ChromaDB** (vector store / RAG). It supports single-shot and piped
prompts, a fixed-role multi-agent pipeline (Scoper → Architect → Worker →
Validator/Critics, with git auto-commit), repo indexing and retrieval-augmented
generation via Chroma, and a full direct Chroma CLI. Anthropic (Claude) is
available as an opt-in cloud chat-model provider for the agent roles, alongside
the local-first default.

## Features

- **Single-shot & piped prompts** (`pipe`) — a prompt argument, piped stdin, or
  context generated by an external command
- **Multi-agent orchestration**: Architect (plans) → Worker (implements, only
  role with the tool catalog) → Validator/Critics (review) → auto-commit to a
  feature branch, with optional Scoper (repo-fact gathering), Librarian (RAG),
  and Summarizer (context compression) roles. Configure via `--team-model`
  (quick-start), `--agentic '<JSON>'` (full control), or a persisted team via
  `manager`
- **Optional Anthropic (Claude) chat provider** (`--chat-provider anthropic`) —
  opt-in per run, chat roles only; RAG/memorize/recall always stay on Ollama
  since Anthropic has no embeddings API
- **RAG via Chroma**: single- or multi-collection queries (a goal needing both
  source code and its commit history can search both collections in one
  query), relevance reranking, and automatic cross-session memory recall
- **Repo indexing** into Chroma using ctags symbol boundaries (`index`,
  requires `universal-ctags` on `PATH`)
- **Automatic collection management** (`chroma-init`) — ensures every
  collection documented in a `db_config.json`-shaped schema file exists,
  idempotently
- **Full direct Chroma CLI**: `embed`, `retrieve`, `chroma-query`, `chroma-get`,
  `chroma-search`, `chroma-create`, `chroma-init`, `chroma-modify`,
  `chroma-fork`, `chroma-ls`, `chroma-delete`
- **Native tool-calling REPL** (`func`, `func-struct`): calculator, DuckDuckGo
  search, web scraping, stock lookup, Browserless, git log/blame/diff, plus
  structured-output examples (weather, disk space)
- **Git integration** — the Worker's changes are committed to a feature branch
  automatically once a round is accepted
- **Shell completions** (`completions`) and **man page generation**
  (`manpage`)
- Configurable model options, streaming output, structured (`tracing`) logging

## Installation

1. **Prerequisites**
   - Rust (latest stable)
   - Ollama running (`OLLAMA_HOST=localhost:11434 ollama serve`)
   - Optional: ChromaDB (via Docker) for RAG/embedding/memory features
   - Optional: `universal-ctags` on `PATH` for `ruchat index`
   - Optional: an Anthropic API key (from console.anthropic.com — separate
     from a Claude Pro subscription) if you want `--chat-provider anthropic`

2. **Build**
   ```bash
   git clone https://github.com/RoelKluin/ruchat.git
   cd ruchat
   cargo build --release
   ```

3. **Run ChromaDB (optional, for RAG/embedding/memory)**
   ```bash
   docker run -p 8000:8000 \
     -v ~/chroma_storage:/chroma/chroma \
     chromadb/chroma
   ```

## Basic Usage

```bash
# Single-shot question, no agent team (just the model given)
./target/release/ruchat pipe -m qwen2.5-coder:14b "Explain the borrow checker in Rust"

# Pipe input in (three hyphens/asterisks/underscores can separate prompt from context)
cat file.md | ./target/release/ruchat pipe

# List local Ollama models
./target/release/ruchat ollama-ls

# Multi-agent orchestration (recommended for real coding tasks): Architect + Worker
./target/release/ruchat pipe --team-model "qwen2.5-coder:14b" "Refactor the CLI argument parsing"

# Same, but with RAG against an indexed collection
./target/release/ruchat pipe --team-model "qwen2.5-coder:14b" --collection repo_src-all-minilm_l6-v2 \
  "Where is the retry logic implemented?"

# Use Claude instead of a local model for this one prompt (needs ANTHROPIC_API_KEY)
./target/release/ruchat pipe --chat-provider anthropic --anthropic-model claude-sonnet-4-5-20250929 \
  "Explain the borrow checker in Rust"
```

### Multi-Agent Orchestration

```bash
# Quick-start: Architect + Worker on one model
ruchat pipe --team-model "qwen2.5-coder:14b" "Implement a new Chroma delete command"

# Full custom config (JSON): every role, plus a Librarian for RAG and a Critic
ruchat pipe --agentic '{
  "iterations": 4,
  "Architect": {"model": "qwen2.5:14b", "temperature": 0.0},
  "Worker": {"model": "qwen2.5-coder:14b"},
  "Validator": {"model": "qwen2.5:14b"},
  "Librarian": {"model": "qwen2.5:14b", "embed_model": "all-minilm:l6-v2",
                "chroma_client": "{\"chroma_server\": \"http://localhost:8000\"}",
                "memory_collection": "repo_src-all-minilm_l6-v2"},
  "Critics": [{"model": "qwen2.5:14b", "name": "Security",
               "task": "Review the implementation specifically for Security concerns."}]
}' "Add support for sparse vectors in queries"

# Persist a team and reuse it without retyping the config every time
ruchat manager init
ruchat manager list
ruchat manager run
```

`--agentic`'s config shape mirrors `db_config.json`'s and each role's own
prompt template (`agent_role/*.md`). Only `Architect` and `Worker` are
required; `Validator`, `Librarian`, `Critics`, `Scoper`, and `Summarizer` are
all optional and enabled by including them.

### Retrieval & Vector Store (Chroma)

```bash
# One-time (or after adding a new collection): ensure everything in db_config.json exists
ruchat chroma-init

# Index a source tree into Chroma using ctags symbol boundaries
ruchat index ./src --collection repo_src-all-minilm_l6-v2

# Embed arbitrary text directly
ruchat embed "Some code or notes" --collection repo_src-all-minilm_l6-v2

# Query — single collection
ruchat chroma-query -q "error handling" -c repo_src-all-minilm_l6-v2 -n 5

# Query — multiple collections at once (each searched independently, results labeled per collection)
ruchat chroma-query -q "error handling" -c repo_src-all-minilm_l6-v2,repo_hist-all-minilm_l6-v2 -n 5

# Simplified get/query/search entry point
ruchat retrieve --mode query -q "error handling" -c repo_src-all-minilm_l6-v2

# Advanced payload-based search
ruchat chroma-search --query "0.1,0.2,..." --limit 5

ruchat chroma-ls
ruchat chroma-get --ids id1,id2 -c repo_src-all-minilm_l6-v2
ruchat chroma-delete -c some-collection --force
```

See `ruchat --help` and each subcommand's own `--help` for the full option
list (there are many — model/generation parameters, Chroma connection/retry
settings, output formatting, and more).

## Configuration

- Config file: `--config <path>` (env `RUCHAT_CONFIG`), defaults to
  `~/.config/ruchat/config.json` or `./ruchat.json`; `--profile <name>` (env
  `RUCHAT_PROFILE`) selects a named profile inside it
- Ollama server: `-s`/`--server` or `OLLAMA_SERVER` (default
  `http://localhost:11434`)
- Chroma connection: `CHROMA_SERVER`/`-C`, `CHROMA_TOKEN`/`-t`,
  `CHROMA_TENANT`, `CHROMA_DATABASE`/`-d`, or the equivalent CLI flags;
  retry behavior via `--max-retries`/`--min-delay`/`--max-delay`/`--jitter`
- Anthropic: `ANTHROPIC_API_KEY` (or `--anthropic-api-key`) plus
  `--anthropic-model` when using `--chat-provider anthropic`
- Model options via `-o`/`--options <JSON|file>`, or the individual
  `--temperature`/`--top-k`/`--top-p`/`--repeat-penalty`/`--num-predict`/
  `--seed`/`--num-ctx`/`--stop` flags
- Persistent team/manager state in `ruchat_manager.json`
  (`manager init`/`list`/`run`)
- Collection schema documentation consumed by `chroma-init` and injected into
  the Librarian's prompt: `db_config.json`
- Logging: `RUST_LOG` controls level (e.g. `RUST_LOG=debug`);
  `RUCHAT_LOG_FORMAT=json` switches to newline-delimited JSON events for log
  aggregators — default is human-readable
